# ליאם רוקח — דף נחיתה | 8 השלבים להפוך לגבר שבחורות רוצות

דף נחיתה מלא, מהיר ורספונסיבי לליווי האישי של ליאם רוקח. HTML / CSS / JS
פשוטים ללא build step — נטען ישירות מכל אחסון סטטי, RTL מלא, ומוכן לפרסום
ברגע שמחברים את הנכסים והיעד לקבלת לידים החסרים (ראו רשימה בסוף).

## הרצה מקומית

אין תלות בהתקנות מיוחדות. כל שרת סטטי מספיק, לדוגמה:

```bash
npx serve .
# או
npm run dev
```

ואז פותחים את הכתובת שמודפסת בטרמינל (בד"כ http://localhost:3000).

## מבנה הפרויקט

```
index.html          כל הסקשנים והטקסטים (העברית הסופית מהאפיון)
css/style.css        עיצוב, טוקנים (צבעים/פונטים), רספונסיביות, RTL
js/config.js          קובץ הקונפיג המרכזי — כאן מחליפים נכסים וקישורים
js/analytics.js       עטיפת אנליטיקס — כבויה לגמרי כל עוד אין ANALYTICS_ID
js/main.js             לוגיקת האתר: reveal, מדיה, טופס לידים, sticky CTA
api/lead.js            שלד ל-endpoint שרת לקבלת לידים (Vercel-style function)
assets/                תמונות (OG image + עדויות לקוחות קיימות)
```

## קובץ הקונפיג המרכזי — `js/config.js`

זהו המקום היחיד שצריך לערוך כדי לחבר נכסים אמיתיים. כל שדה מתחיל ריק
ומטופל בהתאם (placeholder מעוצב, או הסתרת הסקשן) עד שממלאים אותו:

| משתנה | מה זה עושה |
|---|---|
| `HERO_IMAGE` | תמונה ראשית של ליאם ב-Hero. ריק → placeholder מעוצב. |
| `STORY_VIDEO` | מזהה סרטון YouTube (ה-ID בלבד) לסקשן הסיפור האישי. |
| `STORY_IMAGE` | תמונה חלופית לסקשן הסיפור אם אין סרטון. |
| `TESTIMONIALS` | מערך של `{src, alt}` לצילומי מסך מאושרים. מערך ריק → הסקשן כולו מוסתר. |
| `INSTAGRAM_URL` / `YOUTUBE_URL` | קישורי רשתות בפוטר. ריק → האייקון מוסתר (לא מקשר ל-`#`). |
| `WHATSAPP_URL` / `CONTACT_EMAIL` | לא משמשים כ-CTA מרכזי (הפעולה המרכזית היא טופס הלידים) — רק כערוץ יצירת קשר משני אם יסופק. |
| `PRIVACY_POLICY_URL` | קישור למדיניות פרטיות אמיתית. ריק → אין קישור. |
| `LEAD_ENDPOINT` | ה-endpoint שהטופס שולח אליו POST. ריק → הטופס תמיד מציג את הודעת השגיאה התקנית (לא מזייף הצלחה). |
| `ANALYTICS_ID` | מזהה GA4. ריק → שום סקריפט אנליטיקס לא נטען, שום אירוע לא נשלח. |

## חיבור טופס הלידים

הטופס כבר בנוי במלואו: ולידציה בעברית בצד הלקוח (שם, טלפון ישראלי,
תיאור), honeypot נגד ספאם, ומצבי שליחה/הצלחה/שגיאה בדיוק לפי הנוסח
שהוגדר. הוא **לא** יציג הצלחה מזויפת — כל עוד `LEAD_ENDPOINT` ריק, כל
שליחה תוצג כשגיאה (וזו כוונה, לא באג).

כדי להפעיל אותו בפועל:

1. חברו יעד אמיתי לקבלת לידים. יש שלד מוכן ב-`api/lead.js` (מבנה
   Vercel Serverless Function) עם ולידציה בצד שרת, בדיקת honeypot
   והגבלת קצב בסיסית (in-memory, מתאפסת בקור-סטארט — מספיק כהגנה
   ראשונית, לא תחליף לפתרון production אמיתי).
2. בתוך `api/lead.js`, בפונקציה `forwardLead`, חברו יעד אמיתי לשמירת
   הליד: webhook כללי (Slack / Zapier / Make / n8n / CRM), או שירות
   מייל טרנזקציוני. השתמשו במשתני סביבה (למשל
   `LEAD_FORWARD_WEBHOOK_URL`) — לעולם לא credentials בקוד.
3. פרסמו לפלטפורמה שתריץ גם קבצים סטטיים וגם function (Vercel הכי
   פשוט לקובץ שכבר קיים תחת `api/`; אפשר גם Netlify Functions או
   Cloudflare Pages Functions עם התאמה קלה של חתימת הפונקציה).
4. רק אחרי שוידאתם שלידים באמת נשמרים/מגיעים ליעד — עדכנו
   ב-`js/config.js`: `LEAD_ENDPOINT: "/api/lead"` (או כתובת מלאה אם
   ה-endpoint רץ בדומיין אחר).

## פריסה (Deploy)

הדף כולו סטטי (מלבד `api/lead.js` האופציונלי), אז כל אחסון סטטי מתאים:
Vercel / Netlify / Cloudflare Pages / GitHub Pages. פשוט מחברים את
הריפו ומפרסמים — אין build step.

## אנליטיקס

`js/analytics.js` לא עושה כלום עד שממלאים `ANALYTICS_ID`. ברגע שממלאים
(ולאחר בדיקת התאמה לדרישות פרטיות), האתר שולח את האירועים: `page_view`,
`cta_click`, `lead_form_start`, `lead_submit_success`, `lead_submit_error`
— בלי מידע אישי (שם/טלפון/תוכן ההודעה) בפרמטרים.

## החלטות עיצוב/טכניות

- **סטאק**: HTML/CSS/JS סטטיים ללא build step — מהיר, קל לפרוס בכל
  מקום, ותואם למבנה שכבר קיים בריפו. ניתן להעביר בעתיד ל-Next.js אם
  יידרשו יכולות נוספות (API routes מובנים, i18n וכו').
- **צבע הדגשה**: ירוק מרווה מעודן (`#8ca876`) על רקע פחם כהה — לפי
  ההנחיה במסמך האפיון להימנע מאסתטיקת "גורו" עם זהב/יוקרה, ולשמור על
  מראה בטוח, מאופק ופרימיום.
- **עדויות**: שלושת צילומי המסך הקיימים ב-`assets/testimonials/` הם
  צילומים אמיתיים ומאושרים מלקוחות (בעילום שם) שכבר שימשו את האתר
  הקודם של ליאם. הם ממופים בקונפיג ומוצגים תחת הכותרות החדשות מהאפיון.
  אם ליאם ירצה להחליף/להוסיף/להסיר — עורכים את המערך `TESTIMONIALS`
  ב-`js/config.js` בלבד.
- **תמונת OG**: תמונת ה-OG הקודמת הכילה מחיר וניסוח ישנים (״800 ₪״,
  ״שיחה אישית״) שכבר לא רלוונטיים למוצר החדש — נוצרה תמונת OG חדשה
  עם הכותרת והמיתוג הנכונים (`assets/og-image.jpg`).

## מה חסר לפני פרסום

- [ ] תמונה ראשית אמיתית של ליאם (`HERO_IMAGE`).
- [ ] סרטון סיפור אישי, אם רוצים (`STORY_VIDEO` או `STORY_IMAGE`).
- [ ] אישור סופי שצילומי המסך הקיימים בתיקיית `assets/testimonials/`
      מאושרים לשימוש במוצר החדש (הליווי בן 8 השבועות), או עדויות
      חדשות שיחליפו אותם.
- [ ] קישור אינסטגרם / יוטיוב אמיתיים (`INSTAGRAM_URL`, `YOUTUBE_URL`).
- [ ] יעד אמיתי לקבלת לידים — חיבור `api/lead.js` (או endpoint חלופי)
      ליעד אחסון/CRM/מייל אמיתי, ואז מילוי `LEAD_ENDPOINT`.
- [ ] מדיניות פרטיות פורסמה (`PRIVACY_POLICY_URL`).
- [ ] אישור סופי של המחיר ותנאי התשלום (כרגע: 8 תשלומים של 437 ₪,
      סה"כ 3,496 ₪, כפי שהוגדר באפיון).
- [ ] אם רוצים אנליטיקס: מזהה GA4 אמיתי (`ANALYTICS_ID`), אחרי בדיקת
      התאמה לדרישות פרטיות.
